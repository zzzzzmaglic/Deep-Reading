# Task 10：原生知识库浏览设计

**日期：** 2026-08-23
**状态：** 已获产品设计确认；等待本规格审阅后再编写实施计划
**范围：** 仅原生 SwiftUI 的 Task 10「知识库浏览与范围内资产管理」

## 1. 目标与边界

在现有 `ios_visual_prototype` 原生 App 中增加一个真实数据驱动的知识库入口。用户能够浏览文章集合与标签、在集合或标签上下文中查看阅读资产，并在允许的范围内移除关联或删除资产。

本任务不恢复 Flutter 客户端，不接入 AI 搜索/伴读，不实现阅读流首页，也不实现集合或标签的通用新建、重命名、排序、删除或编辑。原有 Task 6–9 的阅读器、划线、资产卡片、标签和“当前文章汇总”保持其已验收的行为。

## 2. 信息架构与导航

App 根视图改用 iOS 26 原生 `TabView`：

- 默认选中 **知识库**。它拥有独立 `NavigationStack`，以便详情页返回时保留列表折叠状态、滚动位置和选择状态。
- **首页** 是明确的“尚未实现阅读流”占位入口；不伪造或提前实现 Task 10 以外的首页内容。
- Tab Bar 不导出成 Figma 位图。使用系统原生 Liquid Glass Tab Bar、SF Symbol 和无障碍语义；仅当 Figma 图标无法确认映射到 SF Symbol 时，才把该单独图标导出为原型自己的矢量 Asset。
- 从知识库详情进入阅读器时，阅读器压入当前知识库的导航栈并隐藏 Tab Bar；返回恢复原详情页及原状态。

```text
首页（占位）  |  知识库（默认）
                     ├─ 集合详情 ── 文章阅读器 ── 返回集合详情
                     └─ 标签详情 ── 来源标题 ── 文章阅读器锚点 ── 返回标签详情
                                    └─ 点资产行 ── 已有阅读资产卡片覆盖层
```

知识库首页遵循 Figma `12`（`114:355`）：集合和标签各自折叠、默认最多展示五项；固定集合 **往期推文** 和系统标签 **摘录与思考** 分别置顶。页面背景为 `#F2F2F7`，顶/底使用与已验收阅读器相同的原生渐进虚化实现，高度均为 116 pt。

集合详情遵循 Figma `13/14`（`116:355`、`118:355`），标签详情遵循 `15/17/18`（`119:355`、`121:355`、`122:355`）。所有阅读资产卡片仍复用当前文章汇总的真实资产卡片覆盖层，不新造第二种编辑器。

## 3. 数据模型与安全契约

### 3.1 真实数据来源

知识库只使用当前 App 已注入的同一个 `SupabaseClient` 与本机/目标 Supabase；不使用静态知识库数据。现有 `SupabaseReadingAssetRepository` 继续提供资产、标签和锚点数据。

新增 `KnowledgeBaseRepository` 负责集合、集合文章预览和用户在集合中的可见性。现有 `ArticleRepository` 保持文章内容与进度职责，不混入知识库列表查询。

为满足 Figma 集合卡片的封面、认知维度和发布时间，在 Supabase 的 `articles` 中新增受控展示字段（例如封面资源标识、认知维度、发布时间）。种子数据写入确定值；原型从自己的 Asset Catalog 按资源标识加载已导出的 Figma 封面，不在运行时依赖临时 Figma URL。

### 3.2 集合的“移除”语义

既有 `collections` 与 `article_collections` 是全局种子关系，不能因某一个匿名/当前用户的操作而被全局改写。因此新增 owner-scoped 的隐藏关系：

`collection_article_exclusions(owner_id, collection_id, article_id, created_at)`，并在 `(owner_id, collection_id, article_id)` 上设唯一约束。

集合详情读取时排除该用户自己的 exclusions。普通集合的多选“移除”写入该表，所以只会从当前用户的集合视图隐藏文章；不会删除文章、不影响其他集合，也不影响其他用户。固定集合 **往期推文** 为系统锁定集合，不能执行此操作。

数据库通过只接受文章 UUID 数组的原子 RPC 执行操作，校验当前用户身份、原始全局归属与集合是否锁定，并以 RLS 限制 owner 只能看到/写入自己的 exclusion。

### 3.3 标签的资产操作

- 普通标签：多选“移除”只删除资产—标签关系，资产、划线、笔记和其他标签关系保留。
- 系统标签 **摘录与思考**：多选“删除”是不可恢复的真实资产删除；采用原子批量 RPC，先完整校验当前用户对全部资产的归属，再统一删除，避免顺序请求造成部分成功、重试重删。
- 标签详情的“新建独立型笔记”预选当前标签。系统标签在产品正式上线时由后端/注册流程为每个用户自动创建并锁定选中；用户无需也不能创建同名系统标签。本轮迁移需使新匿名用户同样获得这一系统标签，不靠客户端补丁伪造。

所有 RPC 只返回业务所需字段；客户端不写入或输出 service-role、JWT secret、DeepSeek 等服务端密钥。

## 4. SwiftUI 组件边界

新增或抽取的职责如下：

| 区域 | 组件 / 协调器 | 责任 |
| --- | --- | --- |
| 数据 | `KnowledgeBaseRepository` / `SupabaseKnowledgeBaseRepository` | 查询集合、标签、可见文章及执行原子集合移除 |
| 首页 | `KnowledgeHomeCoordinator` / `KnowledgeHomeScreen` | 加载、折叠状态、错误与重试 |
| 集合 | `CollectionDetailCoordinator` / `CollectionDetailScreen` | 卡片列表、多选、只对普通集合显示移除 |
| 标签 | `TagDetailCoordinator` / `TagDetailScreen` | 资产排序、多选、普通移除/系统删除、独立笔记预选标签 |
| 共享视图 | `ReadingAssetRow` | 从当前文章汇总抽取的资产行：强调色条、引用/笔记、来源标题与“在文中显示”语义一致 |
| 现有复用 | `ReadingAssetCard` / `AssetDraftController` | 点资产条目直接打开已有查看/编辑覆盖层；卡片保存/删除后刷新详情列表 |

行的可点击区域是完整卡片，唯独“来源标题/在文中显示”是独立按钮：它进入具有文章 ID 和 UTF-16 锚点的阅读器。独立型笔记没有来源标题，也不会跳转阅读器。

读取、删除、移除和保存均为单飞操作：同一协调器在请求未完成时禁用相同提交入口，并以 generation/route 身份拒绝过期异步回写。失败时保留用户选中项与可重试上下文；成功后才刷新列表。系统删除确认使用 Figma `18` 的自定义确认态，普通移除同样需明确确认其“仅移除关联”的语义。

## 5. 视觉规则

- 根页面：393 × 852 pt 的 iPhone 16 / iOS 26 基准；原生动态特性可有系统级差异，但不可用静态图片替代原生交互层。
- 首页分组卡：x=11、宽 371、18 pt 圆角、白色，行高 47 pt、分隔线 `#E5E5EA`；首页标题 34 pt bold、分组标题 21 pt bold。
- 集合文章卡：371 × 106 pt、5 pt 间距、15 pt 圆角；封面 74 × 78 pt、12 pt 圆角。标题 16 pt medium / 21 pt 行高，元数据 11 pt medium / 15 pt 行高。
- 标签资产卡：371 × 169 pt、8 pt 间距、18 pt 圆角。关联型强调色为 `#F6CF48`，独立型为 `#7AA4E7`；沿用当前汇总页的条目结构以防视觉漂移。
- 顶部返回控件、添加独立笔记按钮和 Tab Bar 使用原生 iOS 26 Liquid Glass。阅读器和知识库顶部渐进虚化使用同一已验收代码路径，高 116 pt，不复制另一套近似 Material 遮罩。

## 6. 测试与验收

先写失败测试，再作最小实现。至少覆盖：

1. 新匿名用户获得且无法取消锁定的“摘录与思考”标签；普通标签可移除关联，系统标签批量删除资产。
2. 个人 exclusion 只影响当前 owner，普通集合移除不修改全局 seed 关系，锁定集合拒绝移除。
3. 首页折叠最多五项及展开/收起；固定集合/系统标签排序第一。
4. 集合与标签多选的操作语义、原子失败保留选择、快速重复点击只发一次 RPC。
5. 点击标签资产行打开资产卡片；只有来源标题进入正确文章与锚点；阅读器返回原标签详情并保留状态。
6. iPhone 16 / iOS 26.5：默认选中知识库、详情 back、阅读器 anchor return、普通标签移除和系统标签删除的 UI 流程。
7. 运行 `supabase test db`、目标 XCTest/UI XCTest、`git diff --check`；手工在 Simulator 对照 Figma `12–18` 截图验收。
